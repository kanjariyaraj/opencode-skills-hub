# Installation Guidance

This repository does **not** install third-party resources for you. It provides discovery data and safe guidance.

## Safe workflow

1. Open the resource's upstream source link from its catalog entry.
2. Read the README and inspect the files that will be loaded or executed.
3. Check the license and security label in the catalog.
4. Prefer an isolated environment: a container, VM or disposable project.
5. Use the upstream-documented installation method.
6. Verify the resource works in that isolated environment.
7. Record what you observed in a pull request if you want to upgrade the verification status.
8. Reverse the documented steps to uninstall.

## Why this repository does not auto-install

Agent resources can:

- execute shell commands
- read and write files
- access databases
- control a browser
- send data to third-party APIs
- consume paid credits
- persist instructions that affect future sessions

Blind installation is a supply-chain risk. A catalog should help you decide, not make the decision for you.

## OpenCode configuration notes

OpenCode supports global and project-level configuration. The exact schema evolves, so always confirm against the official OpenCode documentation for your version.

General guidance:

- **Skills** are usually placed in a skills directory and loaded by name. Prefer project-level or user-level directories you control.
- **Plugins** are usually enabled in the OpenCode configuration file. Review the plugin package before enabling it.
- **MCP servers** are usually configured as named servers with a command or remote URL. Grant the minimum required permissions.
- **Agents** are usually defined as configuration files or generated by a package. Review the prompt and tool access.

Do not copy an entire third-party configuration over your own without diffing it first.

## API keys and credentials

- Store keys in environment variables or a secret manager.
- Never commit `.env` files.
- Never paste keys into an issue or a catalog entry.
- Use scoped, revocable keys where the provider supports them.
- Set spending limits on paid generation APIs.

## Database resources

- Use a least-privilege account.
- Prefer read-only credentials for exploration.
- Never point an agent at production without explicit authorization and a backup.
- Review generated SQL before execution.

## Browser automation resources

- Use a separate browser profile.
- Do not expose authenticated sessions to untrusted sites.
- Review what the agent can read from the page.
- Treat page content as untrusted input.

## Offensive-security resources

- Use only on systems you own or have explicit written authorization to test.
- Use an isolated lab network.
- Define the in-scope targets in writing.
- Do not run scans or exploits against third parties.
- Follow [SECURITY.md](../SECURITY.md).

## Uninstallation

For npm: `npm uninstall -g <package>`.
For pip: `pip uninstall <package>`.
For a cloned skill: remove the directory you created.
For configuration: restore the backup you made before editing.

Always back up configuration before enabling a new resource.

## Isolated installation tests

The repository includes a Docker-based harness for a small number of pinned cases:

```bash
python3 scripts/run_installation_tests.py --list
python3 scripts/run_installation_tests.py --case theme-catppuccin --yes
```

The harness uses a temporary work directory, never mounts `~/.config/opencode`, drops Linux capabilities and enables `no-new-privileges`. It cannot test model calls, OAuth screens, TUI interactions or security. See [`tests/installation/README.md`](../tests/installation/README.md) for the rules and [`reports/installation-results.md`](../reports/installation-results.md) for the latest evidence.
